# Using AI Tasks
The AI Tasks feature allows you to define structured tasks that your local LLM can perform. These tasks can be integrated into Home Assistant automations and scripts, enabling you to generate dynamic content based on specific prompts and instructions.

## Setting up an AI Task Handler
Setting up a task handler is similar to setting up a conversation agent. You can choose to run the model directly within Home Assistant using `llama-cpp-python`, or you can use an external backend like Ollama. See the [Setup Guide](./docs/Setup.md) for detailed instructions on configuring your AI Task handler.

The specific configuration options for AI Tasks are:
| Option Name                       | Description                                                                                                                         |
|-----------------------------------|-------------------------------------------------------------------------------------------------------------------------------------|
| Structured Data Extraction Method | Choose how the AI Task should extract structured data from the model's output. Options include `structured_output` and `tool`.      |
| Data Extraction Retry Count       | The number of times to retry data extraction if the initial attempt fails. Useful when models can produce incorrect tool responses. |

If no structured data extraction method is specified, then the task entity will always return raw text.

## Using an AI Task in a Script or Automation
To use an AI Task in a Home Assistant script or automation, you can utilize the `ai_task.generate_data` action. This action allows you to specify the task name, instructions, and the structure of the expected output. Below is an example of a script that generates a joke about a smart device in your home.

**Device Joke Script:**
```yaml
sequence:
  - action: ai_task.generate_data
    data:
      task_name: Device Joke Generation
      instructions: |
        Write a funny joke about one of the smart devices in my home.
        Here are all of the smart devices I have: 
        {% for device in states | rejectattr('domain', 'in', ['update', 'event']) -%}
        - {{ device.name }} ({{device.domain}})
        {% endfor %}
      # You MUST set this to your own LLM entity ID if you do not set a default one in HA Settings
      # entity_id: ai_task.unsloth_qwen3_0_6b_gguf_unsloth_qwen3_0_6b_gguf
      structure:
        joke_setup:
          description: The beginning of a joke about a smart device in the home
          required: true
          selector:
            text: null
        joke_punchline:
          description: The punchline of the same joke about the smart device
          required: true
          selector:
            text: null
    response_variable: joke_output
  - action: notify.persistent_notification
    data:
      message: |-
        {{ joke_output.data.joke_setup }}
        ...
        {{ joke_output.data.joke_punchline }}
alias: Device Joke
description: "Generates a funny joke about one of the smart devices in the home."
```

### Example 2: Smart Home Morning Briefing

Generate a personalized morning briefing that summarizes your home's status, energy usage, and upcoming schedule — all generated by your local LLM.

```yaml
trigger:
  - platform: sun
    event: sunrise
    offset: "-00:30:00"  # 30 minutes before sunrise
condition: []
action:
  - action: ai_task.generate_data
    data:
      task_name: Morning Briefing
      instructions: |
        Create a concise morning briefing for the homeowner. Use the following data to provide a warm, informative summary.
        Keep it under 200 words and write in a friendly, conversational tone.
        
        Current time: {{ now().strftime('%I:%M %p') }}
        Current temperature: {{ states('sensor.outdoor_temperature') | default('N/A') }}°F
        Current humidity: {{ states('sensor.outdoor_humidity') | default('N/A') }}%
        
        Devices currently ON:
        {% for state in states if state.state == 'on' and state.domain in ['light', 'switch', 'fan'] -%}
        - {{ state.name }} ({{ state.domain }})
        {% endfor %}
        
        Doors and windows:
        {% for state in states if state.domain in ['binary_sensor'] and 'door' in state.entity_id or 'window' in state.entity_id -%}
        - {{ state.name }}: {{ 'Open' if state.state == 'on' else 'Closed' }}
        {% endfor %}
        
        Today's weather forecast:
        {{ states('sensor.weather_forecast') | default('No forecast available') }}
        
        Structure your response with these sections:
        1. A greeting with the current time
        2. Outdoor conditions summary
        3. Active devices summary
        4. Security status (open doors/windows)
        5. A brief suggestion or tip based on the data
      structure:
        greeting:
          description: A warm greeting with the current time of day
          required: true
          selector:
            text: null
        outdoor_conditions:
          description: Summary of outdoor temperature, humidity, and weather
          required: true
          selector:
            text: null
        active_devices:
          description: List of lights, switches, and fans currently on
          required: false
          selector:
            text: null
        security_status:
          description: Status of all doors and windows (open or closed)
          required: true
          selector:
            text: null
        daily_tip:
          description: A brief helpful suggestion based on the home data
          required: true
          selector:
            text: null
    response_variable: briefing
  - action: notify.persistent_notification
    data:
      message: |
        **Good Morning!** ☀️
        
        {{ briefing.data.greeting }}
        
        **Conditions:** {{ briefing.data.outdoor_conditions }}
        
        **Active Devices:** {{ briefing.data.active_devices | default('None') }}
        
        **Security:** {{ briefing.data.security_status }}
        
        **Tip:** {{ briefing.data.daily_tip }}
alias: Morning Briefing
description: "Automatically generates a personalized smart home morning briefing 30 minutes before sunrise."
```

### Example 3: Energy Usage Analysis Report

Have your LLM analyze your home's energy consumption patterns and generate a structured report with actionable insights.

```yaml
trigger:
  - platform: time_pattern
    hours: "/6"  # Every 6 hours
condition: []
action:
  - action: ai_task.generate_data
    data:
      task_name: Energy Analysis
      instructions: |
        Analyze the energy consumption data below and generate a structured energy report.
        Identify the highest-consuming devices, estimate daily cost, and provide specific recommendations for savings.
        
        Energy sensors:
        {% for state in states if 'energy' in state.entity_id or 'power' in state.entity_id or 'watts' in state.entity_id -%}
        - {{ state.name }}: {{ state.state }} {{ state.unit_of_measurement | default('') }}
        {% endfor %}
        
        HVAC usage:
        - Living Room HVAC: {{ states('climate.living_room') | default('N/A') }}
        - Bedroom HVAC: {{ states('climate.bedroom') | default('N/A') }}
        
        Solar production (if available): {{ states('sensor.solar_production') | default('N/A') }}
        
        Electricity rate: ${{ states('sensor.electricity_rate') | default('0.12') }}/kWh
        
        Be analytical but accessible. Avoid jargon. Provide specific dollar estimates where possible.
      structure:
        summary:
          description: A one-sentence overview of the home's energy status
          required: true
          selector:
            text: null
        top_consumers:
          description: List of the top 3 highest energy-consuming devices or systems
          required: true
          selector:
            array:
              config:
                mode: list
          selector:
            text: null
        estimated_daily_cost:
          description: Estimated daily energy cost in dollars
          required: true
          selector:
            text: null
        savings_recommendations:
          description: 3 specific actionable recommendations to reduce energy costs
          required: true
          selector:
            array:
              config:
                mode: list
          selector:
            text: null
        solar_offset:
          description: Whether solar is offsetting consumption or if there's a net draw, with brief explanation
          required: false
          selector:
            text: null
    response_variable: energy_report
  - action: notify.persistent_notification
    data:
      message: |
        **⚡ Energy Report**
        
        {{ energy_report.data.summary }}
        
        **Top Consumers:**
        {% for item in energy_report.data.top_consumers %}
        - {{ item }}
        {% endfor %}
        
        **Daily Cost:** {{ energy_report.data.estimated_daily_cost }}
        
        **Savings Tips:**
        {% for tip in energy_report.data.savings_recommendations %}
        - {{ tip }}
        {% endfor %}
        
        {% if energy_report.data.solar_offset %}
        **Solar:** {{ energy_report.data.solar_offset }}
        {% endif %}
alias: Energy Report
description: "Automatically generates an energy consumption analysis report every 6 hours."
```

### Example 4: Security Event Summary

Generate a structured security summary from motion sensors, door/window sensors, and camera events for a daily digest or on-demand review.

```yaml
trigger:
  - platform: sun
    event: sunset
    offset: "-00:15:00"  # 15 minutes before sunset
condition:
  - condition: state
    entity_id: input_select.home_mode
    state: "Away"
action:
  - action: ai_task.generate_data
    data:
      task_name: Security Summary
      instructions: |
        Review the security sensor data below and generate a clear, organized summary report.
        Focus on any unusual patterns, open entries, or events that need attention.
        If everything is secure and quiet, state that clearly.
        
        Motion sensors (last 24 hours):
        {% for state in states if 'motion' in state.entity_id -%}
        - {{ state.name }}: {{ state.state }} (last triggered: {{ state.attributes.last_triggered | default('never') }})
        {% endfor %}
        
        Door/Window sensors:
        {% for state in states if state.domain == 'binary_sensor' and ('door' in state.entity_id or 'window' in state.entity_id) -%}
        - {{ state.name }}: {{ 'Open' if state.state == 'on' else 'Closed' }}
        {% endfor %}
        
        Locks:
        {% for state in states if state.domain == 'lock' -%}
        - {{ state.name }}: {{ state.state }}
        {% endfor %}
        
        Cameras:
        {% for state in states if state.domain == 'camera' -%}
        - {{ state.name }}: {{ state.state }}
        {% endfor %}
        
        Home mode: {{ states('input_select.home_mode') | default('Not set') }}
        
      structure:
        overall_assessment:
          description: One-word assessment: 'Secure', 'Alert', or 'Attention Needed'
          required: true
          selector:
            text: null
        open_entries:
          description: List of any doors or windows currently open, or 'All sealed' if none
          required: true
          selector:
            text: null
        motion_summary:
          description: Brief summary of motion activity — any unusual spikes or late-night activity
          required: true
          selector:
            text: null
        lock_status:
          description: Status of all locks — highlight any that are unlocked
          required: true
          selector:
            text: null
        action_items:
          description: List of any actions the homeowner should take, or empty if none needed
          required: false
          selector:
            array:
              config:
                mode: list
          selector:
            text: null
    response_variable: security_report
  - action: notify.persistent_notification
    data:
      message: |
        **🔒 Security Summary**
        
        **Assessment:** {{ security_report.data.overall_assessment }}
        
        **Open Entries:** {{ security_report.data.open_entries }}
        
        **Motion Activity:** {{ security_report.data.motion_summary }}
        
        **Locks:** {{ security_report.data.lock_status }}
        
        {% if security_report.data.action_items %}
        **Action Items:**
        {% for item in security_report.data.action_items %}
        - {{ item }}
        {% endfor %}
        {% endif %}
alias: Security Summary
description: "Automatically generates a security summary 15 minutes before sunset when the home is in 'Away' mode."
```
